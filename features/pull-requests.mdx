title: "Pull requests: view open PRs from connected Git providers"
description: "Browse open pull requests for a connected repository in Commit+, with status, branch, and author details, then open any PR in your provider's web interface."
---

Commit+ adds a read-only pull request view so you can see what is happening on the remote for the repository you are working on. The list stays focused: open PRs, their status, branches, author, and a quick way to open any of them in the provider's web interface.

## What it shows

When the selected repository uses a connected provider account, the Pull Requests view lists open pull requests for that remote:

- **PR number and title** — scan quickly for the change you care about.
- **Source and target branches** — see where a PR is coming from and going to.
- **Author** — username and avatar, when available from the provider.
- **State** — open, closed, merged, or draft.
- **Last updated** — relative timestamp so you know how fresh the entry is.

Each row also has an **Open in Browser** button that jumps directly to the pull request page on the provider's site.

## How it works

Pull Requests uses the provider account connected to the repository's remote:

1. Select a repository with a supported remote and a connected provider account.
2. Open the Pull Requests view from the main window.
3. Commit+ fetches the current open PRs from the provider API and renders them using normalized models, so the UI stays independent of any single provider's response format.

If no account is connected, or the token has expired, the view prompts you to **Connect Account** or **Reconnect** to continue.

## Currently supported

- GitHub repositories via a connected GitHub account.
- GitLab repositories via a connected GitLab account.
- Azure Repos repositories via a connected Azure Repos account. Commit+ lists pull requests and shows their details and changed files, and you can merge them. Azure Repos has no assignees, so participant details are not shown.

More providers and deeper PR workflows will follow as the provider account layer expands.

## On the roadmap

This is the read phase of pull request support. Future iterations will add create, review, and merge capabilities directly from Commit+.

## View a branch's pull request

Right-click a branch in the sidebar. While Commit+ checks the provider, the menu shows **Checking Pull Request…**, then offers **View Pull Request** when the branch has a pull request, or **Create Pull Request...** otherwise. Commit+ prefers an open or draft pull request and otherwise uses the most recently updated one; when that latest pull request is closed or merged, you can still create a new one. **View Pull Request** opens the pull request in its own detail window. Lookup works with GitHub and GitLab accounts.

## Creation notifications

When creating a pull request from Commit+, macOS can notify you of success or failure. Allow alerts and sounds when prompted. Click the notification to open that repository's **Pull Requests** view, even if its window was closed. Creation results remain available in the app when notifications are disabled. Turn these banners off with **Pull request results** in **Settings → Notifications**.

## Copy and read pull request details

In a pull request's header, use the copy buttons beside the source and target branches to copy their names, or **Copy link** to copy the pull request URL. The header rearranges its controls when space is limited. Descriptions and comments render Markdown, including tables and expandable details. Images from unrelated third-party hosts are blocked.

GitHub review comments include the file path, line range, and available diff context. Comments on older revisions are marked **Outdated**.
